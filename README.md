# 우리 반 캐릭터 진도 위젯

## 최근 수정 사항

- 활동과 차시 이름 옆의 `⋯` 메뉴에서 내용을 수정할 수 있습니다. 활동 내용은 모든 반에 공통 적용되고 완료 상태는 유지됩니다.
- 활동의 `⋯` 메뉴에서 위·아래 순서 변경과 삭제를 할 수 있고, 차시 메뉴에서 차시를 삭제할 수 있습니다. 삭제나 순서 변경은 진도창의 `↶` 버튼 또는 Ctrl+Z로 한 번 되돌릴 수 있습니다.
- 진도창 아래쪽에는 저장 상태와 활동·차시 추가 버튼이 고정되어 있습니다. `↶` 실행 뒤에는 아래쪽 조작 바를 유지해 깜빡임을 줄입니다. 긴 목록은 창 안에서 스크롤할 수 있으며, 아이콘 위에 마우스를 올리면 기능 안내가 표시됩니다.
- 입력 대화상자는 Enter로 확인하고 Esc로 취소할 수 있습니다. 진도창에서 Esc를 누르면 창이 닫힙니다.
- 반 설정에서 캐릭터 크기를 50~150%로 조절하고 캐릭터 위 진도율 표시를 켜고 끌 수 있습니다. 반 이름은 항상 표시됩니다. 이미지는 반 행에 끌어놓아 지정할 수 있고 `×` 아이콘으로 비울 수 있습니다.
- 반 설정의 `저장`과 `닫기` 버튼은 목록 아래에 고정해, 반 목록을 스크롤해도 항상 보이게 합니다.

이 변경 사항은 이 개발 폴더의 소스에 반영되어 있습니다. GitHub에서 배포한 기존 실행 파일에는 아직 반영되지 않았습니다. GitHub 배포를 갱신하려면 버전을 올리고 새 릴리스를 만들어야 합니다.

Windows 바탕화면 아래쪽, 작업표시줄 바로 위에 반별 캐릭터가 투명 배경으로 보이는 위젯입니다. 작업표시줄을 경주 트랙처럼 사용하며 캐릭터는 해당 반의 전체 활동 완료율에 맞춰 결승 깃발 쪽으로 이동합니다. 활동을 체크하면 위치와 이름표의 퍼센트가 갱신됩니다. 캐릭터를 클릭하면 해당 반의 진도 말풍선이 열립니다. 마우스 오른쪽 클릭 메뉴의 「반 개수·캐릭터 설정」에서 반별 이미지를 정하고, 반 이름 바꾸기, 반 추가, 전체 종료를 할 수 있습니다.

처음 실행하면 캐릭터 그림 없이 은은한 `＋` 이미지 자리표시자가 표시됩니다. 오른쪽 클릭 메뉴의 「반 개수·캐릭터 설정」에서 수업하는 반을 1~20개로 맞추고 반별 이름과 이미지를 지정할 수 있습니다. PNG, JPG, WEBP, BMP, GIF 이미지를 선택하거나 해당 반 행에 끌어놓을 수 있고, `×` 아이콘으로 이미지를 비울 수 있습니다. 첫 프레임만 사용하며 20MB 이하, 2,400만 픽셀 이하 이미지를 지원합니다. 선택한 이미지는 `%APPDATA%\UsagiJindo\characters`에 복사되어 해당 PC에서만 사용됩니다. 이미지를 비우면 해당 반은 자리표시자로 돌아갑니다. 반을 줄이면 마지막에 있는 반들의 진도와 메모가 삭제되므로 확인창이 표시됩니다. 각 반의 진도창에는 그 반에만 저장되는 메모가 있으며, 입력 즉시 저장됩니다.

「반 개수·캐릭터 설정」에서 모든 캐릭터의 대기 동작을 「살짝 둥둥」 또는 「멈춤」으로 한 번에 설정할 수 있습니다. 진도에 따라 트랙에서 이동하는 동작은 두 설정 모두에서 유지됩니다.

차시와 활동은 공통 계획으로 관리합니다. 어느 반에서 차시나 활동을 추가해도 모든 반에 같은 계획이 추가되고, 완료 체크는 반마다 따로 저장됩니다. 기본 반은 5~10반이며, 첫 차시에 공기환경·소리환경·빛환경·포스터 그리기가 들어 있습니다. 체크 상태와 계획은 `%APPDATA%\UsagiJindo\progress.json`에 저장하고, 저장할 때 직전 정상 파일을 `progress.json.bak`으로 보관합니다. 저장 도중 문제가 생기면 기존 파일을 교체하지 않습니다. 저장 파일을 읽지 못하면 자동 백업을 복구하고, 손상 파일도 `progress.recovery-날짜-시간.json`으로 보존합니다. 진도와 캐릭터 이미지는 PC에 저장되고 외부로 전송되지 않습니다. 이미지 파일을 추가하는 사람은 해당 이미지의 이용 권리를 확인해야 합니다.

## 업데이트 기능

배포된 앱은 시작할 때 공개 GitHub 저장소의 최신 안정 릴리스를 확인합니다. 새 버전이 있으면 변경 내용을 보여주고, 사용자가 동의한 경우에만 내려받습니다. 캐릭터 이미지와 진도 파일은 그대로 두고 앱 파일만 교체합니다. 업데이트 파일은 GitHub 릴리스의 SHA-256 값으로 확인한 뒤 설치하며, 이전 앱 폴더는 같은 위치에 백업으로 남습니다. 인터넷 연결이 필요합니다. 우클릭 메뉴의 「업데이트 확인」으로 직접 확인할 수도 있습니다. Python으로 `app.py`를 실행하는 개발 모드에서는 업데이트 설치 메뉴가 동작하지 않습니다.

이 앱은 `gajaessam/jindo-widget`의 공개 릴리스를 확인합니다. GitHub Releases API는 공개 저장소에서 인증 없이 사용합니다. GitHub에 릴리스 파일을 올리면 앱은 업데이트 확인 요청을 보내며, 업데이트 다운로드는 앱에서 설치를 선택했을 때 시작됩니다.

### 설치 파일과 자동 업데이트 ZIP 만들기

GitHub Actions를 사용하면 내 컴퓨터에 빌드 도구를 설치할 필요가 없습니다. 직접 빌드하려면 Python 3, Tcl/Tk, Pillow, PyInstaller와 Inno Setup 6 이상이 설치된 Windows에서 프로젝트 폴더의 아래 명령을 실행합니다.

```powershell
python -m pip install -r requirements-build.txt
.\build_release.ps1
```

빌드가 성공하면 `release` 폴더에 설치 파일 `진도 위젯-v0.2.1.exe`와 앱 자동 업데이트용 `UsagiJindo-v0.2.1-Windows-x64.zip`이 만들어집니다. 받는 사람은 설치 파일을 내려받아 실행하면 됩니다. 설치 프로그램이 필요한 구성품을 사용자 폴더에 설치하고 `진도 위젯` 이름의 시작 메뉴 바로가기를 만듭니다. 바탕 화면 바로가기도 설치 중 선택할 수 있습니다.

GitHub Release에는 두 파일을 모두 첨부해야 합니다. 설치 파일은 새 사용자가 내려받아 설치할 파일이고, ZIP은 앱의 자동 업데이트 기능이 사용하는 파일입니다. ZIP은 일반 사용자가 따로 내려받아 풀 필요가 없습니다. 새 저장소의 첫 Release 태그는 `v0.2.1`입니다. 다음 배포 때 `update_config.py`의 `APP_VERSION`을 예를 들어 `0.2.2`로 올린 뒤 빌드하고, GitHub Release 태그를 `v0.2.2`로 지정해 해당 버전의 설치 파일과 ZIP을 함께 첨부합니다. 앱이 업데이트 ZIP을 찾으므로 파일 이름을 그대로 유지해 주세요.

새 저장소와 영문 앱 폴더 이름을 처음 적용할 때는 기존 설치본의 자동 업데이트가 새 저장소로 이어지지 않습니다. 새 저장소의 첫 `진도 위젯-v0.2.1.exe`를 직접 실행해 설치해 주세요. 진도와 반 설정은 `%APPDATA%\UsagiJindo`에 저장되므로 그대로 유지됩니다. 전환한 뒤의 업데이트는 새 저장소에서 자동으로 확인합니다.

빌드 스크립트는 Windows용 앱 폴더와 별도 업데이트 도우미를 만든 뒤, Inno Setup 설치 파일과 앱 자동 업데이트용 ZIP을 생성합니다. Actions 아티팩트에는 두 배포 파일이 모두 들어 있습니다. GitHub Release를 게시할 때는 두 파일을 모두 첨부해야 하며, 사용자는 설치 파일만 받으면 됩니다. 앱 실행 파일과 설치 파일에는 코드 서명이 포함되지 않으므로 Windows가 최초 실행 시 게시자 확인 안내를 표시할 수 있습니다.

## 실행

Python 3와 Pillow가 필요합니다. `시작하기.bat`을 더블클릭해 실행하세요. 실행 중 모든 캐릭터를 종료하려면 캐릭터를 오른쪽 클릭하고 「전체 종료」를 선택합니다. `Ctrl+Shift+Q`도 종료 단축키입니다.

위젯은 프로그램에 동봉된 캐릭터 그림을 불러오지 않습니다. 배포할 때는 원본 캐릭터 이미지 파일을 포함하지 말고 앱 코드와 실행 파일만 배포하세요. 반 설정에서 각자 사용할 이미지를 선택하면 됩니다. 위젯과 작업표시줄 배치는 현재 기본(주) 모니터 기준이며, DPI 배율과 화면 크기 변경을 감지해 위치를 다시 맞춥니다. 보조 모니터에는 위젯을 표시하지 않습니다.
